# Migrating from AMDconfigurations 0.1.0 to 0.2.0

## What does not change

AMD keeps the formula used in the published analyses:

```r
mean(apply(membership, 1, max)) - 1 / ncol(membership)
```

The main argument lists of `compute_amd_curve()` and the direct-data form of
`assign_configurations()` remain compatible. New curve objects retain
`c_opt`, `max`, `mean`, `raw` and `coordinates`; new direct assignment objects
retain `c_opt`, `cluster`, `membership`, `centers` and `objective`.

These compatibility claims were checked against both the installed public
package `AMDconfigurations 0.1.0` and its archived CRAN source. The local
consolidation evidence includes a curve object generated by
that installed package; it is used as a binary compatibility fixture in the
test suite.

## Recommended 0.2 workflow

```r
curve <- compute_amd_curve(
  X,
  its = 20,
  nin = 2,
  nsp = 10,
  seeds = seed_matrix,
  verbose = FALSE
)

plot(curve)

# chosen_c must be justified from the complete curve and the analysis context.
assigned <- assign_configurations(curve, c = chosen_c)
```

`curve$curve` is the primary AMD curve. For every candidate `c`, it contains
the AMD of the converged fuzzy c-means fit with the smallest objective.
`assign_configurations(curve, c)` extracts that exact stored fit and does not
run clustering again.

`curve$c_peak` and its historical alias `curve$c_opt` report only the first
numerical maximum. A boundary maximum, plateau or weak decline requires
interpretation of the complete curve and does not establish a number of
groups by itself.

## Why old and new results can differ

Public version 0.1.0 accepted a `seeds` argument but did not apply those seeds
to fuzzy c-means. It selected `c_opt` from the largest AMD observed across
starts and then ran a new, unrecorded fit to produce `coordinates`.

Version 0.2 applies and records every seed, selects the smallest-objective
converged fit at each `c`, and stores the exact selected membership matrix.
Consequently, the new result is reproducible but need not reproduce accidental
0.1.0 numerical output.

Version 0.2 also rejects candidate ranges whose upper `c` is not smaller than
the number of complete observations. Direct assignment excludes fits that
reach `iter_max` from selection. Version 0.1.0 did not enforce either rule.

## Saved 0.1.0 curve objects

Saved 0.1.0 objects contain `mean`, `max`, `raw`, `coordinates` and `c_opt`,
but not the objectives or fitted memberships needed to reconstruct the new
primary curve. They can still be inspected:

```r
print(old_curve)
summary(old_curve)
plot(old_curve)                 # stored mean, with a warning
plot(old_curve, type = "max")  # stored maximum, with a warning
```

The old `c_opt` marker is shown only with `type = "max"`, because version
0.1.0 obtained it from that series rather than from the mean.

The warning is intentional. Recompute the curve with version 0.2 whenever the
original data and analysis settings are available.

## Historical diagnostics

`curve$mean`, `curve$max` and `curve$raw` remain available for compatibility
and restart diagnostics. They are not the primary curve and must not replace
`curve$curve` in the recommended workflow.

## Sigma-equivalent

Sigma-equivalent has been removed. Existing scripts that call
`estimate_sigma_equivalent()` must retain an archived 0.1.0 environment if
they need to reproduce a historical analysis. The function is not replaced by
another compactness, density or connectivity measure in version 0.2.

## Stored-partition diagnostics

`diagnose_amd(curve)` describes memberships, sizes, curve neighbours and
label-invariant transitions without refitting or selecting K. It does not
measure density, geometric compactness or resampling stability. Missing
neighbours and summaries of empty hard groups remain `NA`; no imputation is
used in this descriptive interface.

## Optional corrected reader

`load_amd_predictor(path, sha256)` and `predict_amd(data, predictor)` provide
optional model assistance. The external bundle is not included in the package
and requires its expected checksum. `ranger` and `digest` are suggested, not
core dependencies; there are no automatic downloads or training operations.

Only the corrected v2 contract is accepted. The historical v1 reader remains
an unchanged study artefact and must use its matching historical extractor.
Changing a feature without matching models is not a supported migration.

The reader's contract fixes c=2:14, 20 principal starts, five computational
refits per c, m=2 and iter_max=2000, without scaling or variable preselection.
A compatible saved curve can replace the principal fits; computational refits
are still required and are not sample-level stability.

The proposed K is the numerically resolved density-mode count used as the
simulation reference, not necessarily the number of generating components.
It is not the numerical AMD peak or an automatic scientific conclusion;
AMD itself does not estimate a density. Off-grid proposals themselves are
labelled exploratory. The two certainties concern correctness of the emitted
one/several-modes decision and of exact K. Their transfer to corrected forests
was assessed retrospectively on the previously examined final bank. By default
they are suppressed outside N={150,600}, D={2,6,15}, observed output support
K=1:8 or assessed missingness patterns. Grid membership does not certify new-data
geometry. The frozen models omitted value columns for zero-variance fraction
(always zero in training) and minimum covariance-rank fraction (always one).
Departures suppress certainty even on-grid and cannot be overridden with
allow_extrapolation. Do not change a dataset just to match the grid. Explicitly retaining
off-grid values does not validate interpolation or extrapolation.

Large data may exceed the working-memory guard; it is not a runtime limit.
Partition distances remain exact, but the frozen global-distance descriptors
use a seeded sample of 2000 rows when N > 2000. Their actual sample count and
sampling flags are reported. No additional approximation bypasses the guard.
The manual curve workflow remains available. Obtain the corrected-v2 bundle
from the matching versioned GitHub release and compare its SHA-256 with the
release manifest before loading it. The CRAN package does not contain or
automatically download the model.
